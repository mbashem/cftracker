        First-time setup · HTTP, CORS, and GitHub OAuth
        
    
          
  1. Run the command below from the repository root. It serves only the tester assets and documentation on loopback. Open http://localhost:8000/backend/api-tester.html. Opening a file:// URL is insufficient for JavaScript modules, cookies, and a usable CORS origin.
    2. 
          
  2. Add the tester's exact origin, such as http://localhost:8000, to the backend's comma-separated CORS_ALLOWED_ORIGINS. Use your existing deployment procedure to apply configuration changes.
    3. 
          
  3. Enter the backend origin in the sidebar. You can immediately test health endpoints or paste an existing token.
    4. 
          
  4. For GitHub sign-in, add this tester's origin to CORS_ALLOWED_ORIGINS and register http://localhost:8000/callback/auth-gh in the GitHub OAuth app. The local tester server also serves this page at that callback path. No backend redirect setting or alternate-domain parameter is needed.
    5. 
          
  5. Click Sign in with GitHub. This page exchanges the returned code using the backend's HTTP-only state cookie, then saves the session token and profile. No client secret belongs in this page.
    6. 
        

        
python3 backend/serve-api-tester.py

        
For local HTTP, use the same hostname for the tester and backend (for example, localhost on both). HTTPS deployments must forward X-Forwarded-Proto correctly. Browser restrictions on cross-site cookies can prevent OAuth even with CORS configured.

        
Requests include cookies, and bearer tokens are sent only to protected endpoints on the selected backend. Redirected API requests are rejected. Responses are displayed as text, never as HTML.

      

      
This tool runs entirely in your browser and is not served automatically by the Go API. API requests can modify real backend data. The request button shows the exact method being sent.
